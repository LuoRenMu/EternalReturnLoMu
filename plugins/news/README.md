# 公告、活动与兑换码插件

`news` 插件只负责原有兑换码、游戏活动指令，不再包含更新公告命令或定时扫描。

更新公告已拆到独立的 [`patch-notes` 插件](../patch-notes/README.md)，使用 `/最新更新`。
升级时先热更新本插件释放旧公告别名，再安装 `patch-notes-1.0.0.jar`，避免两个插件注册相同命令。

## 兑换码发现去重

核心扫描任务以官方文章 `articleId` 为持久化唯一键，成功识别并入库后才标记完成。
重复列表、后续扫描、文章标题变更及应用重启都不会重新识别已完成的文章，也不会改写兑换码的首次发现时间。
无兑换码的文章同样记录为已完成；正文获取、AI 识别或数据库失败则保留重试，空 AI 结果不算完成。
数据库通过 `ON CONFLICT (article_id) DO NOTHING` 原子去重，扫描任务不会重复启动。

玩家查询仍在首次发现当天、到期最后一天附加兑换码字符串，保持原有展示规则。

## 兑换码主动推送

news 插件独立监听并记录群通知权限，每分钟读取现有 AI 新闻扫描入库的兑换码，向明确允许主动消息的群推送（不要求订阅群宠）。未知／关闭通知的群不发送，实际发送前再次检查权限及到期时间。

- 按规范化兑换码（去除外围空白／引号，统一大小写）而非文章 ID 去重；分隔的多个兑换码逐个处理。
- 每码每群两个阶段：首次发现、明确到期时间前 24 小时；首次发现已临近到期合并发送。未知到期时间不使用猜测的 14 天期限。
- 首次扫描时超过 24 小时的历史记录只建去重基线，不当作新码轰炸；仍可在临近到期时提醒。首次阶段只发送给当时已开启通知的群，后来开启的群不补发。
- SQLite `data/group-pet.db` 的 `code_push_event` / `code_push_delivery` 表永久保留阶段及群发送记录，重启、重复文章和重复扫描不会重置。不要删除此文件。
- 发送前原子占用，发送成功记 SENT，失败／超时记 UNCERTAIN，进程中断保留 ATTEMPTED，不自动重试。采用至多一次尝试，优先避免重复，网络故障可能漏发；不承诺外部平台 exactly-once。
- 两插件分别以至少 6.1 秒的间隔限速。平台主动推送资格仍需 QQ 支持，群通知开启不等于平台必定允许主动发送。
- 本次新增 core 的历史兑换码读取方法，部署时主程序与插件需一同更新。

兑换码任务由 news 独立启动和停止，不依赖 group-pet。为兼容既有台账，保留原 data/group-pet.db 文件名，避免迁移导致重复发送。

1.3.1 将插件的数据操作统一改为 Ktorm DSL，表结构保留在 `src/main/resources/sql/`；新增依赖已内嵌，兼容主程序 3.0.3。事件去重与投递记录仍处于同一事务，发送前占用及失败不重试策略不变。核心新闻仓储的 SQL 重构需另行升级主程序才生效。
