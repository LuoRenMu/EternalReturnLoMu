# 群宠战绩订阅插件 1.2.5

仅支持 QQ 官方机器人群聊，使用现有 `match` 插件生成最新对局结算图片，通过 Simbot 主动发到订阅群。

## 命令

- `/群宠 백수`：订阅玩家，第一次记录当前最新对局作为基线，不发送历史战绩。
- `/群宠 列表`：只显示本群玩家名称，每行一个。
- `/群宠 取消 백수` 或 `/群宠 取消 玩家ID`：取消本群订阅，不影响其他群。

每群最多 3 位群宠，本群成员均可添加或取消本群订阅。同一玩家重复添加不重置进度。
一次检查发现多场新比赛时只发最新一局；不补发中间对局。若没有历史比赛，之后第一次发现比赛时推送。

## 自适应间隔

| 最近一局距今 | 检查间隔 |
| --- | --- |
| 小于 2 小时 | 2 分钟 |
| 2 小时至 24 小时 | 10 分钟 |
| 1 天至 7 天 | 30 分钟 |
| 7 天至 30 天 | 2 小时 |
| 至少 30 天，或暂无历史比赛 | 6 小时 |

后台每 30 秒取到期订阅，因此实际检查会有调度与排队延迟；冷号重新上线最多要等当前间隔才能发现。
每次等待 DAK.GG 同步，再强制刷新跨模式的最新对局列表。数据上游本身也可能存在同步延迟。
同一批次内同一玩家合并查询和图片生成，发送进度仍按群独立保存。

## 持久化与失败恢复

- 订阅表 `group_pet` 跟随主程序实际数据库：PostgreSQL 复用主程序连接池及 schema；SQLite 保留 `data/group-pet.db`。
- 主键为群 OpenID + 玩家 ID，保存首次基线、已成功发送对局、最近对局时间、下次查询及失败次数。
- 使用数据库租约排除热更新或并发轮询对同一订阅的重复处理；租约 5 分钟，崩溃后自动到期恢复。
- 只有发送成功才推进对局 ID；查询、渲染或发送失败按 5、10、20、40、80、160、320、360 分钟退避，且不短于该玩家当前活跃度间隔，避免失败使冷号查询变频繁；成功后恢复活跃度间隔。
- 取消后渲染结果在发送前再次检查订阅；已经在 QQ 请求中的发送无法撤回。
- 正常轮询、成功记录后的重启不会重复推送。若 QQ 已接收但响应超时，或进程在成功发送与本地记录之间崩溃，重试仍可能重复一条；主动接口没有可用的端到端幂等键，不能保证严格恰好一次。
- 若昵称被另一账号占用，稳定玩家 ID 校验会阻止误推；改名后可按玩家 ID 取消，再用新昵称订阅。

## 发送与部署

插件包 `group-pet-1.0.0.jar` 自带 `qq-rich-media` 辅助类，可作为独立插件安装。服务器需要现有 `查询对局` 命令可用、QQ SDK 和 SQLite 驱动；均来自当前主程序及 match 插件。
图片走 Simbot 文件上传得到 `file_info`，不依赖公网图片 URL；发送时不携带被动回复 `msg_id` / `event_id`。
发现新对局时，战绩图片与 `主人，您的宠物"xxx"刚刚进行了一场对局喵~` 合并为同一条主动消息，`xxx` 使用本次查询返回的玩家名称；不拆成额外一条文字通知，推送次数仍按一次成功发送计数。
本插件两次主动发送尝试至少间隔 6.1 秒。QQ 账号权限、群主动接收开关、平台频控仍决定真实发送能否成功。
关闭插件会取消后台任务，订阅保留；重新启用后继续。状态文件包含群与用户标识，不提交 Git。

本地回归覆盖分级间隔、首次基线、更新去重、重启恢复、多群合并、发送失败隔离、身份变化、取消、租约、上限事务回滚与 SDK 主动图片请求。
本次开发未向真实群发送消息，也未部署服务器。

## 群主动消息权限

建立订阅和轮询战绩前调用 `GET /v2/groups/{group_openid}/bot_state`，只有 `allow_proactive_msg=true` 才执行；不以本地 GROUP_MSG_RECEIVE 历史事件作为允许依据。

- 未开启时返回提示：该功能需要群主在机器人页面设置并开启主动发送消息。
- 11253（未获平台接口白名单）、字段缺失、超时、查询异常均为无法确认，不误报为未开启，也不执行 Sync、历史战绩查询或图片生成。
- 每轮按群合并检查，一个群订阅多位玩家只检查一次；插件实时检查尝试间隔至少 2.1 秒，不跨轮缓存允许结果。
- 轮询遇到未开启／无法确认时保留订阅、到期时间和推送游标，5 分钟后重新检查权限，不向群发送重复提醒；主动消息关闭时无法可靠主动告知，因此提示通过订阅命令返回。
- 查询、渲染和主动发送失败均保留订阅与推送游标，按现有退避策略重试；不再区分超时、IllegalArgumentException 或其他发送错误，也不会自动取消该群全部订阅。权限检查失败仍暂停并复查，不删除订阅。

news 的权限筛选不变。新 API 封装已随插件打包，无需升级 Simbot；DSL 适配器及 SQLite 方言也已内嵌，兼容主程序 3.0.3。

## 玩家校验与任务清理

建立订阅前先校验昵称格式，再同步确认玩家存在；不存在时明确提示且不保存任务。
轮询仅在同步接口成功响应明确 `not_found=true` 时删除当前订阅任务（按群、玩家及租约限定）。
超时、HTTP 错误、限流、缺失字段和身份不一致不作为不存在处理，继续保留任务并退避重试。

## 七天有效期

订阅成功起有效 7×24 小时，提示北京时间到期时间；有效期内重复命令不续期。到期任务不再轮询或占用新订阅名额，重新订阅重新建立战绩基线。期限持久化，重启不续期；发送前也检查是否到期。旧数据库没有订阅时间的任务迁移后视为已到期，需重新订阅，避免无期限运行。

跨群订阅及错峰轮询复用插件内共享战绩缓存，缓存有效期遵循玩家活跃度（2 分钟至 6 小时），相同昵称的并发请求合并；缓存最多 512 个名称条目。发送游标、期限、失败重试仍按群独立保存。缓存随插件重启清空，失败结果不缓存。

## 插件边界

`group-pet` 是独立插件，仅负责群宠订阅及战绩推送。兑换码推送已归属 `news` 插件；两者不互相依赖，可独立启停。通用 QQ 主动发送、群通知状态访问位于 `qq-rich-media`。
为保留既有状态，公共权限及兑换码推送台账仍沿用 `data/group-pet.db` 的旧文件名，运行 news 不需要加载 group-pet，勿删除该文件。

DAK.GG 已隐藏账号 ID，订阅使用规范化玩家名的 SHA-256 截断值作为内部订阅 ID，不使用战绩中的占位 userNum=1。该 ID 不代表游戏账号 ID；同名账号易主无法由当前接口可靠识别。兼容仅 player_name 的同步结果和 +0900 时间偏移。

每次建立新订阅（含过期后重新订阅）都会绕过轮询缓存重新执行 Sync 存在性校验，再读取战绩基线；有效期内已订阅玩家仍返回重复订阅提示，不续期。昵称格式无效时不请求上游。

主动发送失败统一退避重试；插件关闭引起的协程取消立即停止，不删除订阅。

1.2.3 与 test 1.8.0 配合错峰查询：群宠扫描固定在每分钟第 5／35 秒，直播扫描在第 20 秒；后台上游请求通过宿主已有公共锁串行并间隔至少 1 秒，慢查询也不会互相重叠。手动订阅存在性检查不等待后台队列；玩家自身的活跃度延迟、到期时间和退避策略不变。无需更新 core。

自动删除仅保留玩家同步明确不存在时的对应任务清理，以及正常到期；用户仍可手动取消订阅。

## PostgreSQL 存储与一次性迁移

- 配置 PostgreSQL 且主程序连接成功时，群宠直接复用该数据库的连接池和 schema，不创建另一个 PostgreSQL 配置或连接池。若主程序已按现有策略降级到 SQLite，群宠也使用 SQLite；群宠不会独立悄悄降级。
- PostgreSQL 的玩家订阅 ID、对局 ID、毫秒时间戳均为 BIGINT，避免 32 位溢出。每群 3 人上限通过事务及群级 advisory lock 保护，跨实例同时订阅也不会超额。
- 第一次访问 PostgreSQL 时将旧 `data/group-pet.db` 中的 `group_pet` 全量导入，保存到期时间、推送游标、下次检查时间和失败状态；租约清空。目标已有同键记录不覆盖。
- 导入与 `group_pet_migration` 完成标记在同一事务中，失败整体回滚且下次可重试。重启／重载不重复导入，避免复活 PostgreSQL 中已取消的订阅。
- 原 SQLite 文件不改写或删除；它仍用于 news 插件的群通知及兑换码去重，不能删除。回退旧插件时 SQLite 只能恢复迁移时的状态，若 PostgreSQL 已处理新对局，需停用插件后同步增量再回退，避免旧游标重复推送。
- 此变更仅迁移群宠订阅，news 的兑换码台账和共享通知记录不改变。

本地 PostgreSQL 集成测试通过独立 fixture 实例运行：设置 GROUP_PET_PG_TEST_URL 后执行 group-pet:test；不设置时跳过 PostgreSQL 集成测试，SQLite 回归照常执行。

1.2.2 将业务数据操作统一改为 Ktorm DSL，建表／迁移保留在 `src/main/resources/sql/`；新增依赖已内嵌，可单独热更新到已验证的主程序 3.0.3。

## 推送次数

1.2.4 起仅在 QQ 接口明确返回战绩主动发送成功后计 1 次；订阅确认、手动查询、无更新、权限未开启、图片生成失败、发送失败／超时均不计数。同一玩家向多个群成功推送分别计数，失败群重试成功只增加该群次数。

统计在 `qq_push_statistics` 中按 `push_kind=group-pet`、`group_id`、`subject_id`（内部玩家 ID）保存 BIGINT `push_count`，`qq_push_receipts` 保存成功发送记录及时间，支持按玩家、群或全部累计汇总。配置 PostgreSQL 时使用主程序连接池和 schema；SQLite 模式仍使用 `data/group-pet.db`，不另开私有统计文件。

计数与成功记录使用 Ktorm DSL，在同一事务内去重／递增；并发写入、数据库提交响应丢失后的重试不会重复计数。取消、到期、重新订阅、重载／重启均不清空累计次数；列表继续只显示玩家名称，不添加统计文字。
从升级后的推送开始计数，不推算历史，也不自动合并切换数据库之前的旧统计。统计写入失败最多重试 3 次并记录日志，不触发战绩重发；外部发送与数据库无法原子提交，进程在发送成功与记账之间崩溃可能漏记。
