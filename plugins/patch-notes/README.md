# 最新更新独立插件

## 最新更新

- `/最新更新`：返回最新一篇官方补丁的摘要图片与正文配图；保留 `/更新公告`、`/更新日志` 别名，三个指令共用同一服务与缓存，均不提供历史文章 ID 参数。
- 使用现有 `config.json` 中的 `ai` 配置，未配置 API Key 时不发起公告分析。请求超时、摘要与配图选择均由独立插件处理，不改变宿主全局 AI 客户端；思考模型长正文请求允许 300 秒，取消插件时取消在途请求。
- 插件启用后启动一次扫描，此后每 30 分钟检查官方 `posts/news?category=patchnote`，按发布日期、文章 ID 只选最新一篇再检查缓存。最新篇已缓存时不会继续处理旧公告；失败一分钟后重试，也不回退处理旧公告。不会向群主动推送。
- 插件关闭/重载时取消旧扫描任务；扫描互斥避免重复出图，查询不等待正在进行的 AI 分析。已检测到更新但新图片尚未完成时返回等待提示，不用旧公告冒充最新。
- 优先简体中文公告，缺失时采用英文原文生成中文摘要。按官方文章 ID 与更新时间识别修订；正文分段分析，再合并摘要，不截断长公告的尾部。
- 角色调整独立分类，每条显示“角色名：具体技能/属性的旧值→新值”，保留原文角色名。分段带上文确认归属，合并不省略角色名；缺少名字、泛称“多个角色”或名字不在对应资料中的输出不缓存，下轮重试。

缓存位于应用资源目录 `resources/patch-notes/<文章ID>/`：

| 文件 | 用途 |
| --- | --- |
| `summary.json` | 原文章 ID、标题、发布日期、修订时间、原文链接、AI 摘要、摘要格式版本 |
| `summary.png` | 对应文章的摘要图片 |
| `image.json` | 图片 SHA-256、摘要 SHA-256、模板版本 |
| `media/*.png` | 从该文章正文提取的配图，最多3张，保留原比例 |

先原子保存摘要，再生成并校验 PNG，最后原子发布图片与校验信息。重启后直接复用缓存；图片缺失/损坏时从摘要恢复，避免重复消耗 AI。官方修订、摘要损坏则重新分析。失败结果不写完成标记。运行时 1.0.2 会在下一轮仅重新分析最新篇的旧格式摘要一次；完成前不展示旧摘要，保留已缓存的正文配图和历史文章，成功后后续扫描直接复用。

AI 输出按结构与长度校验，图片注明 AI 摘要不是完整更新日志，不展示链接；官方原文链接仍保留在摘要元数据中。公告内容作为不可信资料处理，不执行其中指令。

配图只从文章正文区域提取，附带附近的章节标题，不使用新闻列表封面。仅接受官方 CDN 的 HTTPS 静态 PNG/JPEG，过滤小尺寸技能图标、页头页尾与 GIF；正文配图原始文件也按文章 ID 持久化。原有文字摘要缓存在下一轮扫描补齐配图，不重新生成文字摘要。

自动配图：提取最多 80 个正文候选的章节、alt 和周边文字，由现有 AI 根据摘要选择最多 3 个数字 ID；不会采用 AI 生成的 URL。这里是上下文关联分析，不是图片像素识别。AI 选择失败时按不同章节轮流选取；每篇最多尝试获取 16 个候选，解码验证尺寸及完整性后原子保存。旧版配图缓存会在下一轮升级选择，复用已有文字摘要及本地原图。

## 验证与部署

运行 `gradlew :plugins:patch-notes:test :plugins:news:test :plugins:patch-notes:jar :plugins:news:jar`。排版预览输出到根目录 `build/previews/patch-notes-design.png`，明确标注为设计示例，不是实际 AI 结果。

插件 ID 为 `patch-notes`，入口 `cn.luorenmu.plugins.patchnotes.PatchNotesPlugin`。AI 请求、摘要、配图选择、公告端点、命令、渲染和定时任务全部位于本模块；只复用宿主通用配置、HTTP 和渲染接口，不向 core 添加更新公告业务逻辑。

对于 SiliconFlow 的 Qwen Thinking 模型，插件同时限制思考预算 1024 token 和最终输出 4096 token；其他提供商保持原请求字段。`max_tokens` 不包含思考 token，相关参数见 [SiliconFlow 官方 API 文档](https://docs.siliconflow.cn/docs/api/chat-completions-post)。截断结果不写入有效摘要缓存。

本模块不打入 QGBOT/OneBot 主程序，仅由 `stageCommandPlugins` / `stageDistributions` 生成独立 `plugins/patch-notes-1.0.0.jar`。复制到服务器插件目录或通过管理后台上传，即可单独启停、重载；升级无需重建/重启宿主。

从旧版 news 迁移时先更新 news 到运行时 1.2.0，再安装本插件；原 `resources/patch-notes/<文章ID>/` 配图缓存直接复用，旧文字摘要按格式版本升级。不删除历史缓存，但不会再抓取或分析历史公告。没有配置 AI 或没有扫描成功时，查询返回等待提示。
